<Note label="Updated 19 October 2026">

I've now used wayfinder, so I've rewritten this to cover it and when I reach for each skill. These skills change quickly, so some details may have moved on again.

</Note>

[grill-me](https://www.aihero.dev/skills-grill-me) is one of Matt Pocock's AI Hero skills, a set of instructions you add to an AI coding agent like Claude Code. It has the agent interview you in rounds until the vague parts of an idea are pinned down, and it doesn't write any files. That makes it my pick for a vague plan, or for a repo I haven't set the rest of the AI Hero skills up in.

On repos where I have run the setup ([setup-matt-pocock-skills](https://www.aihero.dev/skills-setup-matt-pocock-skills), which records where your issues and docs live), I use [grill-with-docs](https://www.aihero.dev/skills-grill-with-docs) instead. It runs the same interview but writes what you agree on into the repo as you go: a `GLOSSARY.md` as terms are resolved, and an ADR (architecture decision record, a short file saying what was decided and why) under `docs/adr/` for anything hard to reverse or worth explaining later. It really wants ADRs to already exist, and if there aren't any it starts suggesting you create one. You can make that work for you by running it first thing on a repo and getting it to write ADRs out of whatever documentation is already there, which is quite nice. I was already writing ADRs by hand, so it fitted straight into that habit, and the format is now consistent across every repo I touch at work.

[wayfinder](https://www.aihero.dev/skills-wayfinder) is for a big piece of work that needs splitting into tasks, and I've found it quite helpful. You tell it where you're trying to get to, and it opens a map issue on your issue tracker with a child issue for each decision still to be made. Most of those are grilling sessions with you, but some are prototypes or research an agent can go off and do on its own, and you resolve one per session. Wayfinder itself only plans. Once the map is clear, the `to-spec` and `to-tickets` skills from the same set turn it into implementation issues that you can triage and hand to agents to build. It works with GitHub, GitLab, Linear, Jira or plain markdown files, but GitHub suits it best because sub-issues and blocking links show which tickets are ready to pick up.
